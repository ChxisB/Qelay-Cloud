# Porting provenance

Qelay-Cloud ports code from [Qelay](https://github.com/ChxisB/qelay) (MIT, Copyright (c) 2024 Egeo Minotti). The upstream
notice is kept in [LICENSE](../LICENSE).

**Rule:** every ported file gets one row below, in the same change that adds it. A row says where the code came from,
at which upstream commit, and what was changed or dropped. A file with no row is not ported code.

- **Upstream repo:** `../qelay`
- **Upstream commit:** `c43442c9`
- Upstream is a read-only input. Never edit it from this repository.
- **Spike rows** are gone. `packages/store-postgres/spike/` (the task 01 port of the hot path and the doorbell and
  database-access spikes) was removed in task 40, with the rows that described its files. What the port needed and
  what was changed by hand is written up in [spike 01](spikes/01-postgres-port.md). `scripts/port.ts` stays for
  upstream syncs; its default output directory is `packages/store-postgres/spike/ported`, which no longer exists, so
  pass `--out`.
- **Schema (task 11).** The schema modules were not promoted file by file. `src/schema/ddl/` is one clean version-1 DDL
  written from them, and `src/schema/migrate.ts` replaces their drift machinery (see the rows below). The spike copies
  were deleted with the spike (task 40), so `src/schema/` is the only schema.
- **Store (task 12).** `src/store/` is written from the upstream admission code, not copied: upstream
  admitted one job per transaction and carried flows, parents and events, and this store admits a batch as set-based
  steps (lock, read what exists once, decide in memory, write each kind of change in one statement). The matching
  spike copies were deleted with the spike (task 40).
- **Store (task 14).** `complete`, `fail`, recovery, TTL expiry and the DLQ are written from the upstream outcome code, not
  copied. Upstream decided retry or failure in two places (the worker's `fail` and its recovery); here `settleAttempt` does it
  for both. The flow, repeat and cron-lease parts of those files are not ported (tasks 15 and 50). The matching spike copies
  were deleted with the spike (task 40).
- **Store (task 15).** The journal, its retention, logs, the panel's read models, throughput, queue configuration and the
  three retention steps of the tick (`clean`, completion records, group state) are written from the upstream code and
  differ from it where a row below says so; the cron and worker modules of the same task have their own rows. **The
  plan said task 15 empties `spike/ported/`; it could not.** `spike/harness.ts` imported the ported admission, context and
  transaction code, and the `doorbell/`, `doorbell-aws/` and `db-access/` spikes imported `harness.ts`. Task 15 deleted
  the two files that nothing imported (`maintenanceSchedule.ts` and `shared/timers.ts`), task 20 removed `db-access/`
  (and the `doorbell/` files only it imported), and task 40 removed `doorbell-aws/` and `doorbell/`, and with them
  `harness.ts`, `claimOnce.test.ts`, `leaseRecovery.test.ts`, `crashingClaimer.ts` and `ported/`.
- **Control API (task 30).** `packages/control-api` is new code: nothing in `../qelay/src/infrastructure/server/` is
  copied, because upstream's HTTP server is a hand-written layer over its in-process queue manager with a single shared
  token. Its response shapes follow what `../qelay-control-panel` reads today, so the panel works with a change of base
  URL. The panel is a second upstream (MIT, same author): the two rows below put two of its files into `test/contract/`,
  one verbatim and one as the two decisions it makes about `/health` and `/ready`, so a change in the panel shows up as
  a failing contract test here. Both are deleted when task 33 gives the panel a shared types package. The panel commit is `8ebf9328950a23a2f2687115a0ec15e66b7659bd`, not the Qelay commit above.

- **Flows (task 50).** The flow rows below are adapted from upstream's flow code, not copied: upstream wrote a flow
  through one admission call per job and resolved parents with several statements and a client-side poll; here a
  flow is one transaction and a parent is released inside the transaction of the child that finishes last. Each file
  carries an "Adapted from" line naming its sources. The flow model harness is original (its row says what it takes
  from upstream's).
