# 73 — Release preparation (v1.0.0)

**Status:** prepared locally; **acceptance bullet 3 not met** (the owner has not decided workflows or signed off the scope) · **Depends on:** 22, 37, 41, 43, 51, 52, 62, 70, 71, 72 · **Phase:** 6

## Goal

Decide what ships in v1.0.0, make it releasable, and stop. This task prepares the release; it does not publish, tag, push or bump a version without the user's explicit instruction (rule in `CURRENT.md`).

## Scope

In: the scope decision (including the workflow cut), final verification, changelog, licences, package metadata, release checklist.
Out: publishing to npm, creating tags, pushing, announcements: all need the user's go-ahead.

## Steps

1. **Scope decision (D7):** review the state of Phase 5. If workflows are not at the same quality bar as the rest (model test green, crash tests green, no open high finding), recommend cutting them from v1.0.0: hide the capability, keep the code on a branch or behind the flag, note it in the changelog as v1.1 work. Present the recommendation and wait for the user's decision.
2. **Full verification:** the gate commands, the standard and deep model runs, the scenario suite on every transport emulator, the e2e suite, the docs check, `terraform validate` for every module. Real-cloud runs: record which were done (D9) and which were not.
3. **Open issues:** list every known limitation and open finding in `docs/known-issues.md`; none that corrupts data or loses jobs may remain open.
4. **Licences:** the MIT notice with the upstream copyright lines in every package; `THIRD_PARTY_NOTICES.md` generated from the dependency tree; `docs/PORTING.md` complete (module, upstream commit, change summary).
5. **Package metadata (D10):** names, `exports`, `files`, `engines` (Bun 1.4.2 or later, per D12), repository and homepage fields, provenance enabled for publishing. Check the npm names are available and report the result; do not reserve or publish them.
6. **Changelog and version:** `CHANGELOG.md` for v1.0.0 listing features, the compat table summary, limitations and the migration notes. Prepare the version bump as a diff or branch; do not run it.
7. **Release checklist** `docs/release-checklist.md`: the exact steps and commands the user runs to tag, publish and deploy, with the order and the rollback path.
8. **Sign-off:** a final summary for the user: what is in, what is out, what was verified on real clouds and what was not, and the risks they are accepting.

### Findings, and what was done about each

1. **A clean checkout did not typecheck.** `scripts/` and `test/` import `@aws-sdk/client-sqs`, which no root `package.json`
   declared; the working tree passed only through stale root symlinks left by the early spikes. `bun install
   --frozen-lockfile` plus `typecheck` failed with TS2307 in five files. Fixed by declaring it as a root devDependency
   (3.1140.0) and updating `bun.lock`; the clean copy then passed. CI would have failed the same way.
2. **A clone without `.claude/` fails `docs:check`.** Eight links in `docs/security/phase2-pass.md` and `docs/spikes/` point
   into `.claude/.planning/v1.0.0/`, which is untracked. With the planning files copied in, the check passes. This is
   recorded in the release checklist (step 2) and known issues; the owner decides whether to commit `.claude/.planning/` or
   change the links. Not fixed here because it is a decision about the repository's contents.
3. **The first e2e run failed 70 of 70, with no test running**: Playwright 1.62.1 wanted browser builds that were not
   installed (the cache held an older chromium build and no WebKit). That is the sandbox, not the code. I ran
   `bunx playwright install chromium webkit` (public browser downloads, about 170 MiB) and reran: 70 of 70 passed.

### Checks that are not mechanical

- **`docs/PORTING.md` completeness.** Row to file: every `packages/...` path in the table exists. File to row cannot be

- **npm names.** `qelay-cloud` and all ten `@qelay-cloud/*` names answered 404 (free). Ownership of the `@qelay-cloud` scope

- **Provenance** needs a CI runner npm supports and a publishing workflow; `.github/workflows` has none.

### Scope recommendation (D7): ship workflows, with caveats

Evidence: the differential model and the `wfengine` invariants are green; 20 of 20 scenarios pass on every transport
emulator; the crash tests pass; the workflow e2e specs pass on Chromium and WebKit; no high finding is open. Caveats the
owner accepts by shipping: three upstream invariants are relaxed (known issues row 4) and need confirming; upstream's own
workflow suite was not ported; the tick skips `waiting` runs (a single-run recover reaches them); a lost publish waits up to
five minutes; viewers see payloads; migrations 9 to 11 have not run on PG 16. To cut instead:
`QCLOUD_API_WORKFLOWS=false` as the default, and list workflows as v1.1 in the changelog (checklist step 0).
