**Checked** (what was true, with the tests that show it)

- *Fail twice, then succeed:* one delivery, three attempts (500, 503, 200), the documented waits, one success counted, a failing receiver
  does not fail the tick. A receiver that never succeeds ends `failed` after the attempt budget; a manual retry gives a fresh budget and
  attempt numbers keep rising.
- *Four concurrent ticks:* each attempt is sent once, in the store (`SKIP LOCKED` claim) and through the whole sender. A late outcome after
  a lease lapsed is dropped (`stale`) and the newer attempt stands.
- *Signature:* a fixed vector, the receiver example in `docs/webhooks.md` run as written (accepts what the sender signs; refuses a changed
  body, a wrong secret, a stale or future timestamp, a malformed signature and a re-stamped captured signature).
- *SSRF:* the URL matrix (loopback in decimal, octal, hex, short and fullwidth spellings, IPv6 compressed, long, mapped, NAT64 and 6to4,
  metadata names and addresses, every private, shared and special-use range, credentials, `localhost` variants), a name with one private
  answer among public ones refused whole, a rebinding resolver (one resolution; the connection goes to the checked address; a name that
  flips on its next resolution is refused), every redirect status refused and its `Location` never contacted, and the dev-mode flag
  needed on both the Control API and the tick.
- *The wire:* a real-socket client reads only the status line (a 600 KB body after it is never read), caps a line with no break, bounds
  the whole exchange with one deadline (a receiver that sends a byte every 30 ms still times out), and writes a 2 MB body whole. TLS is checked against the
  name with an added test CA.
- *The API:* no read, test, history or enable response carries the secret, for an operator or a viewer; every documented mutation writes
  one audit row by `webhook=<id>` and never by address or secret, a refused and a rejected call too; `docs/openapi.yaml` equals the served
  routes.
- *The panel:* history shows status, attempts and last error and says "signed" or "unsigned"; Retry is sent once under a same-tick double
  click; a short secret is refused before any request; a generated secret is 64 hex digits, sent once and cleared; a viewer sees only the URL's
  origin and has no nav link (e2e).
- *The docs are the code:* `test/docs/webhooks.doc.test.ts` compares the replay window, the retry schedule, the sender defaults, the
  sizes, the events and the headers in `docs/webhooks.md` with the constants that set them.

**Decisions**

- One queue per webhook (a filter column; empty means every queue) instead of a list: a narrowing of the task's "queues filter". A
  receiver that wants two queues registers two webhooks.
- Unsigned webhooks are allowed and flagged (`signed`; the panel shows "unsigned"). A signed webhook whose secret cannot be opened is
  never sent unsigned.
- No redirect is followed, no response body is read or recorded, and no resolved address appears in an error.
- No job data in the body (the receiver reads the job through its own credentials). No ordering guarantee.
- Registration validates the URL string and never resolves the name; the send-time check is the defence.
- Viewers see the URL's origin only (`urlRedacted`); the audit target is `webhook=<id>` and nothing else.
- `features.webhooks` is derived from the jobs routes being served, as `features.flows` is.
- The panel page is operator-only through the capabilities gate that already existed. The panel requires 16 to 256 characters of secret and
  can generate one, which it shows once.
- The sender is a tick step at operator scale. Fan-out and volume belong in a separate delivery queue run by the SDK; the step does not grow.
- A store error in the sender marks the tick failed; a failing receiver does not.

**Found and fixed**

- `Bun.SQL` `tx.array(values, type)` throws on a null element for BIGINT and INTEGER and writes the text "null" for TEXT with no error. The
  webhook queries use `jsonb_to_recordset(${JSON.stringify(rows)}::text::jsonb)`. **Other code in the repo was not swept for this.**
- A source comment and a test title said the retry budget was "about four hours". It is 63.5 minutes (corrected; the built `dist/*.d.ts`
  still carries the old comment until the next build).
- A controlled `Input` with `onChange` did not update React state under the panel test helpers' `setInput`, while `onInput` did. The secret
  field uses `onInput`, as the URL field does. The cause in happy-dom or the helper was not found.
- The doc test ran the documented example through the `Function` constructor, which the linter refuses (`no-implied-eval`). It now compiles
  the block and loads it as a module.
- A hung shell from a bare `cat > file` waiting on stdin was stopped; no effect on the repo.
