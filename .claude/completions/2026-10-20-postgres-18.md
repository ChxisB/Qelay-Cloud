# 2026-10-20 — PostgreSQL 18 is the target (tests, CI, examples, infra, documented minimum)

Requested by the owner ("Can we change PG to latest e.g. 18?", then "Yes we need to move to postgres 18 so we're on latest",
which is the go-ahead for `infra/` and for raising the minimum). Nothing is committed, pushed or published, and no cloud
resource was touched.

## Changed
- **Test, CI and example Postgres:** `docker-compose.test.yml` (`postgres:18-alpine`, TLS service `postgres:18`),
  `.github/workflows/ci.yml` and `nightly.yml` (4 service images), `examples/orders/docker-compose.yml`.
  Both compose `tmpfs` mounts moved from `/var/lib/postgresql/data` to `/var/lib/postgresql`: the 18 image keeps PGDATA at
  `/var/lib/postgresql/18/docker` and declares `VOLUME /var/lib/postgresql`. The TLS key at `/var/lib/postgresql/server.key`
  now lands on that tmpfs too.
- **Infra (plan only):** `infra/gcp/modules/database` (`POSTGRES_18`), `infra/aws/modules/database` (`engine_version` default
  `"18"`, parameter groups `postgres18`, named `-pg18` and `-pg18-cluster`), both READMEs.
  `scripts/terraform-plan-assertions.ts`, `terraform-plan-aws-background.ts` and `terraform-plan-aws-data.ts` assert 18.
- **Documented minimum is now "PostgreSQL 18 or later"** (`CHANGELOG.md`, `docs/quickstart-local.md`,
  `docs/quickstart-kubernetes.md`). The "PostgreSQL 16 owed" notes are gone from `docs/known-issues.md`, `docs/limits.md`,
  `docs/release-checklist.md` and `DESIGN.md`. The version comments in `CLAUDE.md`, `CONTRIBUTING.md` and the orders README say 18.

## Not changed, on purpose
- `DESIGN.md:513` ("measured … against Postgres 16"), spike docs and `.claude/completions/*`: measurement history.
- No code checks the server version, so nothing in `packages/` changed. The 18 floor is a documentation and test decision.

## Owed or not run
- **The two compose services were not booted on 18.** Docker Desktop was opened but its engine never answered `docker info`,
  so the tmpfs path rests on the image's documented layout, not on a run. Check with
  `docker compose -f docker-compose.test.yml up -d --wait postgres` and `--profile tls up -d --wait postgres-tls`.
- **Infra strings are unconfirmed against the clouds.** `POSTGRES_18` follows the Cloud SQL enum pattern and Cloud SQL lists
  18 as GA and its default; `postgres18` and `engine_version = "18"` follow the RDS pattern and RDS lists 18.x. A wrong value
  fails at apply, not at plan. Check with `aws rds describe-db-engine-versions --engine postgres --default-only` and the
  `gcloud sql instances create --database-version` help (both need the owner's go-ahead for account access).
- An existing deployed instance would need an in-place major upgrade; this repo has never deployed one (D9). The new
  parameter-group name (`-pg18`) forces a new group.
- GitHub Actions has never run these workflows; the CI edit is an image tag only.
- The read-plans throughput test is plan-sensitive (it failed once locally on 18 with a Sort plan, passed in the last gate).
